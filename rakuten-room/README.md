# 楽天ROOM 運用エンジン

楽天市場のデータから、楽天ROOMの**商品選定・紹介文・投稿順・投稿時刻**を自動で組み立てるエンジンです。
依存パッケージなし（Node.js 18 以上と標準ライブラリのみ）。

> **はじめての方へ** — ターミナルの知識は要りません。`START-HERE.md` から読んでください。
> コマンドはすべてClaude Codeに実行させ、あなたは日本語で頼むだけで運用できます。

```
楽天市場で拾う → スコアを付ける → 別キーワードで裏を取る → 実績で補正する
→ 枠に選ぶ → 導線順に並べる → 棚を均す → 紹介文を作る → 時間割に落とす
→ NG検査 → 投稿台本を出す
```

---

## 最初に: 自動化できる範囲

| 工程 | 自動化 |
| --- | --- |
| 商品の発見・選定 | **完全自動**（楽天ウェブサービスAPI） |
| 売上速度の計測 | **完全自動**（レビュー件数の定点観測） |
| 紹介文の作成 | **完全自動**（ルールベース＋任意でLLM） |
| 投稿順・導線の設計 | **完全自動** |
| 投稿時刻の決定 | **完全自動** |
| NG行動の検査 | **完全自動** |
| **楽天ROOMへの投稿実行** | **アダプタ差し替え式（既定は手動）** |

楽天ROOMには公開の投稿APIがありません。ブラウザ操作による無人投稿は楽天の利用規約に抵触する可能性があり、
アカウント停止のリスクを負います。初動で一度つまずいた後の作り直しで、アカウントごと飛ぶのは最悪の結果です。

そのため本エンジンは、**「いつ・何を・どの文で出すか」を完全に確定させたキュー**を成果物とし、
投稿の実行だけを `src/post/adapters/` で差し替える設計にしています。

- `manual`（既定） — 投稿時刻が来たら画面とファイルに本文を出す。貼るだけ。規約リスクなし
- `webhook` — Discord / Slack に飛ばす。スマホの通知からその場で貼れる
- 自作モジュール — `{ name, post(posts) }` を書けば何でも差し込める（自己責任）

実運用では 1投稿あたり15秒程度の貼り付け作業だけが残ります。判断はすべてエンジン側が終えています。

`probe` は30件を取得して各フィールドの充足率を出します。

## 使う順番

### 1. ジャンルを決める

1ジャンルに絞り切るのが前提です。ジャンルがバラバラだとアルゴリズムに「何の棚か分からない」と判断されます。

```bash
node bin/room.js genre 0          # 大ジャンル一覧
node bin/room.js genre 100938     # 子ジャンルを掘る
```

決まったら `config/strategy.json` の `genre.rootGenreId` と `genre.subThemes` を書き換えます。
`subThemes` は「1ジャンルの中の棚」です。ここに書いたキーワードだけを楽天市場で検索します。

### 2. 候補を集める（毎日）

```bash
node bin/room.js collect
```

- `subThemes` の全キーワード × 3つのソート軸 × 2ページ ＋ ジャンルランキングを取得
- ハードフィルタ（★4.0以上 / レビュー100件以上 / 価格レンジ / 在庫あり）を通す
- その日のレビュー件数を `data/snapshot-YYYY-MM-DD.json` に記録

**この定点観測が売上速度の実測値になります。** 初日は差分が無いので売上速度は「未計測」扱いです。
2日目から効き始め、日数を重ねるほど精度が上がります。毎日回してください。

### 3. 初動30件を作る（最重要）

```bash
node bin/room.js launch
```

アルゴリズムは最初の30件に極端に重い比重を置くため、ここだけ別ルールで組みます。

- 全30件をゴールデンタイム（20-23時）に配置
- サブテーマは3〜4個に限定
- 評価取り14 / 売上12 / 送客4
- 1ショップ3商品まで

出力は 2つ。

- `data/plan-launch-YYYY-MM-DD.json` — 機械が読む計画
- `out/plan-launch-YYYY-MM-DD.md` — **人が読む投稿台本**（本文をそのまま貼れる）

### 4. 投稿する

```bash
node bin/room.js next          # これから出す投稿を見る
node bin/room.js now           # 投稿時刻が来たものを出す
node bin/room.js done 1,2,3    # 貼り終えたら投稿済みにする
```

`now` を cron / タスクスケジューラに5分間隔で仕掛けておくと、時刻が来たものだけが出てきます。

```cron
# 毎朝3時に収集して、その日の計画まで作る
0 3 * * *        cd /path/to/rakuten-room && node bin/room.js daily
# ゴールデンタイム中は5分おきに、時刻が来た投稿だけを通知する
*/5 20-23 * * *  cd /path/to/rakuten-room && node bin/room.js now --adapter=webhook
```

一度提示した投稿は再通知されません（`notifiedAt` を記録するため）。
もう一度出したいときは `node bin/room.js now --again` を使ってください。

### 5. 実績を入れる（ここが効く）

```bash
node bin/room.js record 1,2 --likes=24 --clicks=61 --cv=2 --revenue=4980
node bin/room.js report
```

楽天ROOMの内部スコアは外から読めません。読めない以上、こちらで代理指標を積みます。

| ROOMの隠しスコア | 本エンジンの代理指標 |
| --- | --- |
| 閲覧誘導スコア | クリック ÷ いいね |
| CV誘導スコア | 成約 ÷ クリック |
| 外部送客スコア | 送客投稿のクリック比 |

実績が6件たまると、効いたサブテーマ・価格帯・ショップを次の選定に自動で反映します（最大±15%）。

### 6. 通常運用

```bash
node bin/room.js plan --days=3
```

初動と違い、日中の下地スロット（7:40 / 12:20 / 18:10）も使い、1日22投稿まで配置します。

## 何を根拠に商品を選んでいるか

6つの軸の加重和です。重みは `config/strategy.json` の `weights` で変えられます。

### adHeat — 広告加熱度（0.22）

楽天は広告出稿量を公開しません。そこで**販促投資の痕跡**を積み上げて推定します。

| シグナル | 意味 |
| --- | --- |
| アフィリエイト報酬率の引き上げ | 店舗が販促費を積んでいる直接的な証拠 |
| ポイント倍率 / ポイント期間設定 | キャンペーン実施中 |
| クーポン表記・セール文言 | 同上 |
| **別キーワードでも上位に出る** | 露出が買われている（最も強いシグナル） |
| ジャンルランキング掲載 | 実際に売れている |

### trust — 信頼度（0.20）

★4.0以上・レビュー100件以上はハードフィルタで通過済み。その上で
★の高さ（4.0-4.8で段階評価）、レビュー件数（対数スケール）、
ショップ・オブ・ザ・イヤー受賞、候補内での同一ショップの商品数（＝品揃えの厚さ＝大手度）を見ます。

### velocity — 売上速度（0.22）

「レビュー欄で売上スピードを確認する」を機械化したものです。
スナップショットの差分から **レビュー増加件数/日** を出します。
値引き・ポイント増・ランキング上昇は、売上が動く直前のサインとして加点します。

計測できない商品は0点ではなく中庸（0.35）にします。データが無いことを不利にしすぎないためです。

### priceFit — ゴールデン価格帯（0.16）

1500〜2980円が中心。1980〜2680円をピークとする台形分布。
外れるほど落ちますが0にはしません（送客投稿では高額品も使うため）。

### aiFit — 楽天のAI検索が見る6項目（0.12）

| 項目 | 実装 |
| --- | --- |
| 商品名に含まれる動詞 | `copy-lexicon.json` の動詞辞書と照合 |
| 月間検索数の上昇ワード | `trend-words.json` の rising と照合（`room trend` が候補を提案） |
| 類似商品の購買データ | 同サブテーマ内でのレビュー件数の相対順位 |
| カテゴリ相関性 | 設定ジャンルとの距離（同一 / 子 / 関連 / 圏外） |
| 過去30日間の売上速度 | velocity を再利用 |
| トレンド商品の隣接効果 | ランキング商品と同じショップ・同じ棚か |

### craft — 商品ページの作り込み度（0.08）

画像枚数、商品説明の長さ、キャッチコピーの有無、商品名にサイズ・段数などの仕様が入っているか。
作り込まれている店ほど売る気があり、着地後の離脱が少なくなります。

### 役割別スコア

同じ商品でも役割によって良し悪しが変わるため、役割ごとに重みを掛け替えます。

- **評価取り（bait）** — 安さと作り込みを重視。1980円超はスコアを落とす
- **売上（cv）** — 価格帯・売上速度・信頼を重視。★4.2未満は明確に減点
- **送客（traffic）** — 広告加熱と選択肢の多さを重視。色・サイズ展開が多いほど加点

## 投稿の並びをどう決めているか

### 評価 → 売上 → 評価 → 売上

楽天ROOMは直前の行動リズムを強く引き継ぎます。
評価取り投稿でクリックと回遊を起こした直後に売上投稿を出すことで、初速クリック・成約率・CV誘導スコアが乗ります。

実装上、**「売上投稿は必ず評価取り投稿の直後」を構造的に壊れない形で保証**しています。
パターン文字列を頭から消費する方式だと末尾で評価取りが尽きて売上が連続する事故が起きるため、
先に〈評価取り＋売上〉のペアを確定させ、その隙間に評価取り単発と送客を配る方式にしています。

売上商品には、可能な限り**同じ棚（サブテーマ）の評価取り**を充てます。直前に見せたものと地続きなほどリズムが乗ります。

### 導線（バースト）

連続する最大4投稿を同じサブテーマで固め、ジャンルに一過性を持たせます。
同じ棚の商品が続くと、1つクリックした人が隣も見ます。上限に達したら別の棚へ切り替えます。

紹介文には「ひとつ前の◯◯と並べる前提で選びました」のように、前の投稿への参照を自動で入れます。

### 棚として整える

高級品の隣に激安品を置くと購買心理が落ちます。ROOMは並びがそのまま棚として見えます。
役割の並び（評価→売上）は絶対に触らず、**同じ役割の商品どうしを入れ替えて**価格の段差だけを均します。
隣接する投稿の価格比が2.4倍を超えたら違反として扱います。

## 紹介文の作り方

NG:「便利な収納ラック」＝商品名＋感想だけの自己満日記。
OK:「キッチンの置き場問題が一瞬で消える収納ラック」

**誰の / どんな悩みが / どう変わるか** を必ず1文に入れます。

```
毎日3食つくる人へ。サイズが合わずに諦めた隙間が、伸ばして合わせるだけで収納に変わる。
迷ってた人はここ。 ★4.4（1830件） / ポイント5倍 / 送料無料
ひとつ前の水切りラックと並べる前提で選びました。
#キッチン収納 #浮かせる収納 #暮らしの整え方
```

- 「悩み」と「変化」は、商品名から特徴を検出して決めます（`copy-lexicon.json` の `featureRules`）
  - 商品名での一致を説明文より優先します。保存容器の説明文に「伸縮」とあるだけで伸縮商品として売ると文が噛み合わないためです
- 役割ごとに文の仕事を変えます
  - **評価取り** — 価格フックから入る。売り込まない
  - **売上** — 変化を先に出し、★・レビュー数・ポイントで背中を押す
  - **送客** — 「ページで選ばせる」CTAで楽天市場へ送る
- 同じ商品なら毎回同じ文になります（乱数ではなく商品コードのハッシュで選択）
- `ANTHROPIC_API_KEY` を入れると、3要素を保ったまま言い回しだけをLLMで整えます（任意）

## 出す前の検査

`launch` / `plan` は必ず NG検査を通ります。**停止項目が1つでも出たら、その計画は使えません。**

| 検査 | 停止条件 |
| --- | --- |
| NG1 ジャンル散乱 | サブテーマが上限＋1を超える |
| NG2 買い理由0の投稿 | 3要素が欠けた紹介文が1件でもある |
| NG3 売れない価格帯 | ゴールデン価格帯が55%未満 |
| NG4 棚の破壊 | 価格段差が全体の15%超 |
| NG5 時間外投稿 | 売上投稿が評価取りの直後にない |
| NG6 AI最適化 | （注意のみ）AI適合の平均が0.42未満 |

検査結果は投稿台本の先頭にも書き出されます。

## 設定ファイル

| ファイル | 中身 |
| --- | --- |
| `config/strategy.json` | 全パラメータ。ジャンル・価格帯・時間帯・比率・重み。**コードを触らずここだけで調整できます** |
| `config/copy-lexicon.json` | 紹介文の語彙。ペルソナ・悩み・特徴ルール・フック文 |
| `config/trend-words.json` | 上昇ワード。`rising` は手動、`auto.observed` は `collect` が自動で溜めます |

`room trend` が昇格候補を出します。**レビューが速く増えている商品の名前に共通して現れる語**を上昇ワードとみなす仕組みです。
売れている実物から語を逆算しているので、検索ボリュームの推測より実態に近くなります。
誤検出を混ぜないため、`rising` への昇格は手動です。

## つまずいたとき

**「スコア基準を 0.62 → 0.54 に緩めました」と出る**
候補が足りていません。`config/strategy.json` の `genre.subThemes` にキーワードを足して `collect` し直してください。
初日は売上速度が未計測のため全体のスコアが低く出るので、数日 `collect` を回すと自然に解消します。

**「1ショップ3商品までの上限」で枠が埋まらない**
30件出すには最低10ショップぶんの候補が要ります。キーワードを増やすか `filters.maxItemsPerShop` を上げてください。

**「売上投稿を並びから外しました」と出る**
`mix` の `bait` が `cv` より少ないと、対になる評価取りが足りません。`bait ≥ cv` にしてください。

**紹介文が商品と噛み合わない**
`config/copy-lexicon.json` の `featureRules` に、その商品ジャンル特有の語と「悩み → 変化」を足してください。
ここを厚くするほど文が具体的になります。
