# はじめに読む — 移行手順と操作マニュアル

ターミナルやコマンドの知識は不要です。
**やることは「Claudeに日本語で頼む」だけ**で、コマンドはすべてClaudeが実行します。

- このファイル … あなたが手を動かす部分（移行手順・毎日の運用）
- `README.md` … 仕組みの説明
- `HANDOFF.md` … 技術的な引き継ぎ事項（ローカルのClaudeが読みます）
- `CLAUDE.md` … ローカルのClaudeが毎回自動で読む申し送り

---

# 第1部 — 移行手順（初回だけ）

上から順に、7ステップ。**各ステップに「できたかの確認」を付けてあります。**
確認が取れてから次へ進んでください。所要時間はおよそ1時間です。

---

## ステップ1 — ファイルをパソコンに置く

ブラウザで下のリンクを開きます。ZIPファイルがダウンロードされます。

```
https://github.com/longcape/claudeamazon/archive/refs/heads/claude/rakuten-room-automation-8c13zi.zip
```

開かない場合は手動で: GitHubのリポジトリページ → 左上のブランチ名を
**`claude/rakuten-room-automation-8c13zi`** に切り替え → 緑の **Code** ボタン → **Download ZIP**

ダウンロードしたZIPを**ダブルクリックして解凍**し、出てきたフォルダを**デスクトップに移動**します。

> ⚠️ ブランチの切り替えを忘れると `rakuten-room` フォルダが入っていません。ここだけ注意。

**✅ 確認** — デスクトップのフォルダを開いて、中に `rakuten-room` フォルダがある

---

## ステップ2 — Claude Code を入れる

<https://claude.com/claude-code> からダウンロードしてインストールします。ターミナルは要りません。

**✅ 確認** — アプリが起動する

---

## ステップ3 — フォルダを開く

Claude Code で、**開くフォルダとして `rakuten-room` を選びます。**

> ⚠️ その1つ上（`claudeamazon-...`）ではありません。`rakuten-room` そのものです。
> 1つ上を開くと、無関係な別プロジェクトとして扱われます。

**✅ 確認** — 次のように聞いて、`rakuten-room` と答えが返る

```
いまどのフォルダで起動していますか？CLAUDE.md は読み込まれていますか？
```

---

## ステップ4 — 動くかどうか確かめる

そのまま貼ってください。

```
このフォルダは楽天ROOM運用エンジンです。
CLAUDE.md と HANDOFF.md と START-HERE.md を読んでください。

私はターミナル操作に慣れていません。コマンドは全部あなたが実行してください。
私がやる必要のあることだけ、その都度ひとつずつ指示してください。

まず、このパソコンで動く状態かを確認したい:
- Node.js が入っているか（無ければ入れ方を教えてください）
- npm test が29件通るか
```

Node.js が入っていなければ、そこで入れ方を案内してくれます。指示に従ってください。

**✅ 確認** — 「テスト29件すべて通りました」と返ってくる

---

## ステップ5 — 楽天のIDを2つ取る

ブラウザでの作業です。無料で、その場で発行されます。

### ① アプリID（商品データを取るための鍵）

1. <https://webservice.rakuten.co.jp/> を開く
2. 右上から**楽天会員IDでログイン**（普段の楽天のIDでOK）
3. 「アプリID発行」のページへ進む
4. アプリ名（`room-tool` など何でも可）とアプリURL
   （自分のサイトが無ければ楽天ROOMのマイページURLでOK）を入力
5. 発行された **アプリID** をコピー（20桁くらいの数字）

### ② アフィリエイトID（報酬を受け取るための鍵）

1. <https://affiliate.rakuten.co.jp/> にログイン
2. アフィリエイトIDを確認してコピー
   （`1a2b3c4d.5e6f7g8h.9i0j1k2l.3m4n5o6p` のようなピリオド区切りの文字列）

楽天ROOMを使っているなら、すでに発行されています。
①の管理画面に一緒に表示されていることもあります。

> 画面の文言が違っていても慌てなくて大丈夫です。
> **Claudeに「この画面のどこを押せばいい？」と聞けば案内してくれます。**

### ③ Claudeに渡す

```
楽天のIDが取れました。.env に設定してください。
アプリID: （ここに貼る）
アフィリエイトID: （ここに貼る）

設定したら doctor と probe を実行して、問題がないか教えてください。
```

`.env` はパソコンの中だけに保存され、GitHubには上がりません。

**✅ 確認** — probe の結果で、全項目に `○` が付いている

`×` や `△` が出たら、**そのまま先へ進まないでください。**
その項目に対応する判断材料が機能していない状態です。Claudeに原因を調べさせてください。

## ステップ6 — 扱う商材を決める

**ここだけは、あなたにしか決められません。**

初期設定は「インテリア・寝具・収納」のサンプルです。自分のジャンルに変えます。

```
私が扱いたいのは「（例: キッチン用品 / 美容グッズ / ペット用品）」です。
config/strategy.json をこれに合わせて書き換えてください。
キーワードの候補も一緒に提案してください。

書き換えたら probe をもう一度実行して、そのジャンルでも
データがちゃんと返るか確認してください。
```

まだ決まっていなければ、そう言えば一緒に決められます。

```
どのジャンルにするか決まっていません。
楽天市場のジャンル一覧を見ながら、一緒に決めたいです。
```

**✅ 確認** — 書き換え後の probe でも全項目 `○`、かつ
「ハードフィルタの通過率」が0件でない

---

## ステップ7 — 最初の収集を回す

```
今日のぶんの候補を集めてください。
```

3分ほどかかります（楽天のサーバーに負荷をかけないよう、1秒に1回の速度で取得します）。

**✅ 確認** — 「候補◯◯件を保存しました」と返ってくる。件数が数百あれば十分

件数が極端に少ない（50件未満など）場合は、キーワードが商材とズレています。
`候補が少なすぎます。キーワードを見直してください` と頼んでください。

# 第2部 — 毎日の運用

## 1〜2日目 — 集めるだけ

```
今日のぶんの候補を集めてください。
```

売上の勢いは「レビュー件数が昨日から何件増えたか」で測ります。
そのため**初日は比較する相手がおらず、精度が出ません。**
2〜3日は集めるだけにしてください。焦らないことが結果的に一番の近道です。

## 3日目 — 最初の30件を作る

```
初動の30件を組んでください。
```

楽天ROOMのアルゴリズムは**最初の30件を極端に重く評価**します。
ここだけは急がず、データが貯まってから組んでください。

できあがると `out` フォルダに投稿台本が出ます。中身はこうなっています。

```
### 1. 20:05　[評価取り]　1,980円
**商品**: シンク下 収納ラック 伸縮 2段
**リンク**: https://hb.afl.rakuten.co.jp/...

**投稿文（このまま貼る）**
狭いキッチンで戦っている人へ。シンク下のデッドスペースが、
伸ばして合わせるだけで収納に変わる。
#キッチン収納 #暮らしの整え方
```

**この投稿文とリンクを、楽天ROOMにそのまま貼るだけ**です。

## 投稿するとき

```
そろそろ投稿の時間ですか？次に出すものを見せてください。
```

貼り終えたら報告します。

```
1番と2番を投稿しました。
```

## 4日目以降

```
今日の投稿計画を作ってください。
```

## 週に1回 — 結果を教える

楽天ROOMとアフィリエイトの管理画面で数字を見て、そのまま伝えます。

```
先週の実績です。
1番: いいね24、クリック61、成約2件、売上4980円
2番: いいね12、クリック18、成約0件
```

```
これまでの成績を見せてください。
```

**これが効きます。** 実績が6件を超えると、
どのジャンル・価格帯・時間帯が当たっているかを学習して、次の選定に反映します。

# 第3部 — 守ってほしい3つ

### 1. ゴールデンタイムは20時〜23時

投稿計画はこの時間に自動で寄せられます。**この時間に貼れる日を選んで**計画を作ってください。

### 2. 台本の順番を崩さない

「評価取り → 売上」の並びには意味があります。
評価取りで見てもらってから売上を出すと成約率が上がる、という設計です。
**順番を入れ替えたり、売上投稿だけ抜き出して投稿しないでください。** 効果が落ちます。

### 3. `data` フォルダを消さない

売上の勢いの記録と、「どの商品をもう投稿したか」の履歴が入っています。
消すと**同じ商品を二度投稿してしまいます**。

月に一度、こう頼んでください。

```
data フォルダをバックアップしてください。
```

# 第4部 — 困ったときの頼み方

そのまま貼れば通じます。

| 状況 | 言い方 |
| --- | --- |
| エラーが出た | `こんなエラーが出ました。（画面をコピーして貼る）どうすればいいですか？` |
| 何をすればいいか分からない | `いまどういう状態ですか？次に何をすればいいですか？` |
| 投稿文がしっくりこない | `out の台本を10件読んで、文が商品と合っているか見てください` |
| 商品がイマイチ | `選ばれた商品の質が低い気がします。原因を調べてください` |
| 成果が出ない | `これまでの実績を分析して、何を変えるべきか教えてください` |
| 用語が分からない | `「評価取り投稿」ってどういう意味ですか？` |
| 手順を忘れた | `START-HERE.md を読んで、次に何をすればいいか教えてください` |

**分からないことは全部Claudeに聞いて構いません。** それが一番速い方法です。
手順を暗記する必要はありません。
