## テスト期間中の決まりごと

**原則として機能は足さない。** 次の重大な不具合だけは、見つけたらすぐに直す。

- 操作できない（ボタンが押せない、画面が進まない）
- データが消える
- ログインできない
- 保存できない
- スマホで主要な操作ができない
- セキュリティの問題

**それ以外（使いにくい・こうしてほしい・この機能がほしい）は、記録するだけで変えない。**
複数のテスターの結果が集まってから、まとめて優先順位を決める。
1 人の声で直すと、次のテスターが別の場所で詰まる理由が分からなくなる。

## 進め方（3 段階。この順番を崩さない）

### 第 1 段階：URL だけ渡して自由に触ってもらう

渡すのは URL と、次の一文だけ。**操作の説明はしない。**

> VALORANT の試合で使うツールを作りました。説明なしで、好きに触ってみてください。
> PC でもスマホでも構いません。

ここでは何も頼まない。何を最初に押すか、どこで手が止まるか、何を使わないかを見る。

### 第 2 段階：やってほしいことを 1 つずつ頼む

1 つ終わってから次を頼む。**やり方は教えない。** できなかったら、できなかったこととして記録して次へ進む。

1. 次の試合で使う戦術を 1 つ作ってください
2. 作った戦術に、エージェントの立ち位置などを置いてください
3. 作ったものが消えないように保存してください
4. コミュニティから、ほかの人の戦術を自分用に取り込んでください
5. 自分の戦術をみんなに公開してください
6. 気になる投稿に「いいね」を付けてください
7. 問題のある投稿を見つけたつもりで、通報してみてください

> 4 と 6 と 7 は、コミュニティに誰かの投稿が無いとできない。
> そのため見本の投稿を 2 件入れてある（下の「見本の投稿」）。1 人目のテスターから全部頼める。
> 7 は「【通報操作の確認用】」の投稿を通報してもらう。

### 第 3 段階：Google フォームに答えてもらう

ページのいちばん下（フッター）にある「ご意見・不具合の報告」から回答してもらう。
**第 1・第 2 段階が終わるまでフォームの存在は伝えない。** 先に質問を見せると、そこを探して触るようになる。
同じ理由で、アプリの最初の案内にもフォームへの誘導は書いていない。

フォームで聞くこと:

1. 何をするアプリか、すぐに分かりましたか（分かった / 少し迷った / 分からなかった）
2. いちばん分かりにくかった場所はどこですか
3. 使わなかった機能はありますか。なぜ使わなかったですか
4. あったらいいと思った機能はありますか
5. おかしな動きやエラーはありましたか。何をしたときですか
6. 使ったのは PC ですか、スマホですか
7. 使ったブラウザは何ですか（Chrome / Safari / Edge / その他）

## 見本の投稿（2026-09-11 投入）

テスター 1 人目から全部のタスクを試せるよう、本番のコミュニティに 2 件入れてある。
投稿者は運営者のアカウントで、投稿者名は `SAMPLE`。

| | 投稿 A | 投稿 B |
| --- | --- | --- |
| id | `e949db19-17da-4ba7-bddd-efda594164e9` | `5439ff5c-7759-44f8-a36f-ddcb9a53d8ce` |
| 名前 | B メイン 2 枚スモーク → 即設置 | 【通報操作の確認用】この投稿を通報してください |
| 使い道 | 取り込み・いいね | 通報 |
| 通報 5 件で自動で隠れるか | **隠れる**（通常どおり） | **隠れない**（運営者が対象外にした。監査ログ id 4） |

- **投稿 B** はテスター全員が通報する前提なので、自動で隠れる対象から外してある。
  何人が通報しても表示されたまま。通報は 1 人 1 回として数えられる
- **投稿 A** は通報される想定ではないので通常どおり。誤って 5 件集まって隠れたら、
  運営者の「非表示も表示」→「復旧」で戻す

### テストが終わったら

テスターが自分で投稿した戦術は**利用者のデータなので消さない**。見本の 2 件だけを消す。
消す前に、付いたいいねと通報の数を控えておく（テストの結果として使える）。
どちらも Supabase の SQL Editor で実行する。

```sql
-- 1. 消す前に数を控える
select p.name, p.likes, p.reports,
       (select jsonb_object_agg(reason, n)
          from (select reason, count(*) n from public.tactic_reports r
                 where r.post_id = p.id group by reason) x) as reasons
from public.tactic_posts p
where p.id in ('e949db19-17da-4ba7-bddd-efda594164e9', '5439ff5c-7759-44f8-a36f-ddcb9a53d8ce');

-- 2. 見本 2 件を消す（付いたいいねと通報は一緒に消える）
delete from public.tactic_posts
where id in ('e949db19-17da-4ba7-bddd-efda594164e9', '5439ff5c-7759-44f8-a36f-ddcb9a53d8ce');
```

監査ログは、投稿を消しても `post_id` が空になって残る（記録として残す設計）。

## 分かっている弱点（テストで出ても想定内）

- **同じページを 2 つのタブで開くと、後から保存した方で上書きされる。**
  タブ同士で内容を合わせる仕組みが無い。1 つのタブで使う前提
- **スマホでは「マッチ開始」までの縦のスクロールが長い**（マップ・10 人分の枠・戦術の一覧の下）
- 配置盤の進行ルートは、スマホでは 1 本ずつ消せない（「すべて消去」でまとめて消す）
- **スマホとタブレットの配置盤は縦に長い。** 味方の一覧 → 盤面 → 敵の一覧の順に縦に並ぶので、
  盤面にたどり着くまでスクロールが要る。一覧から盤面へ指で引きずるより、
  一覧でエージェントやスキルを 1 回タップして選び、盤面をタップして置く方が楽
- **スマホで置いた後は「置くモード」が続く。** 同じものを続けて置けるようにしているため。
  このままマークをタップすると、選ばれずにもう 1 つ置かれる。消すときは、盤面の上に出る
  「✕ JETT」のような表示を先に押して置くモードを解除し、それからマークをタップすると
  「削除」ボタンが出る（2026-09-11 に実機相当の条件で確認済み）。テストで詰まりやすい場所
- 戦術の種類（EXECUTE / FAST / STACK など）が英語のまま
- Supabase の無料プランは、しばらく使われないと止まる。止まるとコミュニティとログインが使えない
